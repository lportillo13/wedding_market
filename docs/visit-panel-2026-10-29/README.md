# Boutique visit request — editorial side panel B

The owner chose **B — Editorial side panel** from the [three desktop/mobile previews](../visit-modal-options-2026-10-29/README.md). The visit action now opens a native modal dialog: a 480px right panel on desktop and a 94dvh bottom sheet on phones. The existing storefront/outfit remains mounted beneath it, preserving gallery state and page position. The panel uses admitted boutique/outfit photography, a contained company logo or initials, light GT Super title, regular Acumin labels, optional-details disclosure, real policy/fee summary and a persistent action footer.

The old full-page form was moved into `features/boutiques/client/BoutiqueVisitPanel.tsx`; there is only one request implementation. Hero, submenu, boutique information and outfit-detail actions open that same panel. The actual selected outfit is prefilled; storefront requests remain general. Existing required preferred date/time, Costa Rica timezone, optional fields, profile wedding date, consent, authenticated-couple restriction and idempotent fingerprint/submission key remain. The client limits selection to the server's existing five-outfit maximum. Requests still await boutique confirmation and do not reserve outfits or create service booking/review rights. No duplicate name/email collection or payment feature was added.

The native dialog makes the background inert. Explicit Tab-boundary handling keeps focus in the panel; Close, Escape and backdrop dismissal restore focus and page scrolling. Close/dismissal are disabled while a request is in flight. The central body scrolls independently with a fixed close control and action/footer; reduced-motion users get no entrance animation. No package, database, RLS, infrastructure or native release change is required.

## Validation and publication

Architecture, TypeScript, lint and final production build pass; all 110 existing web tests pass. The initial accessibility lint findings were resolved by using a native dialog listener for backdrop clicks, consistent with the existing menu, and removing the obsolete image-lint directive from the parent.

Local production-preview checks cover desktop, 390px phones and 320×568 short screens, with no horizontal overflow or browser errors. Tab/Shift+Tab stay in the dialog, Escape/Close restore the request trigger and scrolling, general requests have no outfit preselected, outfit requests select the current garment, and the fifth selected outfit disables other unchecked choices. The selected gallery photo survives opening/closing. Required date/time and consent prevent incomplete submission. English/Spanish labels work. The final short-screen styles show the preferred-date input above the fixed footer.
