# Independent vendor bookings — October 20, 2026

The owner confirmed that a group inquiry can book several vendors independently, because each vendor has its own private conversation. The owner chose isolated test data instead of dedicated live login accounts. This supersedes the earlier pending one-winner decision in the October 19 workflow review.

## Behavior

- Acceptance now books only the current vendor. Other invitations, proposals and private messages remain available until their own archive, decline or expiry. One proposal can be accepted per vendor thread; repeated acceptance is idempotent and a later revision cannot replace a booked price.
- Email and phone consent, acceptance notifications, review eligibility and accepted follow-up are scoped to that vendor. A client can review both a booked photographer and a booked venue from the same inquiry. The review page chooses a vendor when an old unscoped link leads to multiple bookings.
- Web/native readers use the invitation booking, rather than the old shared `rfqs.accepted_quote_id`. Existing summary RPCs project per-thread booking metadata for compatibility. The acceptance explanation and native confirmation make the independent behavior clear. The accepted web conversation links to that vendor's review form.
- Migration 007 backfills existing bookings and preserves proposal/message history and manual archives. It only reopens closures explicitly generated by the former `accepted_other_vendor` rule, without extending invitation expiry. Preflight found no such closures in this project. Existing booked consent is preserved. Privileged booking fields and accepted status cannot be forged through direct participant updates.
